# Asset importing

The engine does not load DCC files (`.gltf`, `.glb`, `.obj`, `.png`, …)
directly at runtime. They are **imported** once, ahead of time, into a tree
of self-describing binary files that the game references by path. This is
the Unreal/Godot model: a source artist file is an input to a build step,
not something the shipped game reads.

```
assets/hero.glb   ──(import)──▶   content/hero/mesh_0.gasset
                                  content/hero/material_0.gasset
                                  content/hero/skeleton_0.gasset
                                  content/hero/scene.gasset
                                  content/.registry.toml   (updated)
```

- **Source files** live wherever you like (`examples/*/assets/` by
  convention). They are never read by the running game.
- **Content assets** (`*.gasset`) are the game-ready form: one file per
  sub-asset, each carrying a small header plus a `bincode` payload. They
  are committed to version control alongside the code.
- **Addresses** are plain paths (`content/hero/mesh_0.gasset`). The game
  loads by address; there is no opaque content hash to look up.

## Importing a source file

```sh
cd examples/tech-demo
cargo run -p import -- assets/forest.glb
cargo run -p import -- assets/UAL1.glb
```

Run from the directory that owns the `content/` tree — that directory is
the *project root*, and `import` writes `content/…` under it. It prints
every asset it wrote:

```
imported assets/UAL1.glb -> 126 assets
  scene -> content/UAL1/scene.gasset
  mesh/0 -> content/UAL1/mesh_0.gasset
  animation/53 -> content/UAL1/animation_53.gasset
  ...
```

`import` picks the importer by file extension:

| Extensions           | Importer        | Emits                                              |
|----------------------|-----------------|---------------------------------------------------|
| `.gltf` `.glb`       | `GltfImporter`  | `mesh/*`, `material/*`, `texture/*`, `skeleton/*`, `animation/*`, `scene` |
| `.obj` (+ its `.mtl`)| `ObjImporter`   | `mesh/*`, one `material/<mtl stem>`, `scene`       |
| `.png` `.jpg` `.jpeg`| `ImageImporter` | one `main` texture                                |

### Flags

```
import <source> [--config <content.toml>] [--ext <ext>] [--content-root <dir>]
```

- `--config <content.toml>` — load config from an explicit file; its parent
  directory becomes the project root. Without it, `import` reads
  `content.toml` from the current directory if present, otherwise uses the
  defaults below.
- `--ext <ext>` — content-asset file extension, without the dot
  (default `gasset`).
- `--content-root <dir>` — top-level content directory, relative to the
  project root (default `content`).

### `content.toml`

Optional, at the project root. Only `import` reads it — the runtime learns
the extension from the address and the root from `ContentAssetRoot` (below).

```toml
extension = "gasset"   # default
root = "content"       # default
```

## The content tree

`import` writes each sub-asset to a deterministic address:

```
<root>/<source-file-stem>/<sanitised-sub-asset-name>.<ext>
```

- `<source-file-stem>` is the source file name without its extension, so
  `assets/ninja/ninja.glb` → `content/ninja/…`.
- The sub-asset name (`mesh/0`, `animation/53`, `material/steel`) has `/`,
  `\`, and `#` replaced with `_`, so `animation/53` → `animation_53.gasset`.

Cross-references *within a source* are rewritten to these addresses at
import time: a scene's `MeshComponent` ends up holding the `AssetId` of
`content/ninja/mesh_0.gasset`, not of `ninja.glb#mesh/0`.

The content tree is **committed to git**. It is regenerated by re-running
`import`, not by a hidden build step, so a stale tree is a visible diff.

## The `.gasset` file format

```
magic "GRDY" (4 bytes)
u32   header length, little-endian
      bincode(ContentAssetHeader)
      payload — the asset's own bincode encoding, verbatim
```

`ContentAssetHeader` (see `essential::assets::content`):

| Field            | Meaning                                                        |
|------------------|---------------------------------------------------------------|
| `format_version` | `CONTENT_FORMAT_VERSION` (currently `2`); a mismatch is rejected on read |
| `asset_id`       | `AssetId::from_path(address)` — a v5 UUID derived from the address string |
| `references`     | the `AssetId`s this asset points at, so a tree can be integrity-checked by scanning headers alone |
| `kind`           | the asset type tag (`Mesh`, `StandardMaterial`, `Scene`, …); must match the loading type |
| `provenance`     | `Some(ImportProvenance { source, sub_asset })` for import output, `None` for editor-authored assets |

The header can be read without touching the payload, which is what lets a
future tool index a whole content tree cheaply.

## The asset registry

`<root>/.registry.toml` maps every content asset's `AssetId` to its
address:

```toml
[assets]
"9f3c…e21a" = "content/UAL1/scene.gasset"
"b75e…8457" = "content/UAL1/mesh_0.gasset"
```

The runtime needs it only for **path-less loads**. A scene's serialized
`MeshComponent` carries a bare `AssetId` (no path); when the spawner
upgrades that `Weak` handle to `Strong`, `AssetServer` resolves the id to
an address through the registry. Path-based `load::<T>("content/…")` calls
never touch it — the address *is* the lookup.

`import` and `save_content_asset` both upsert the registry (merge-only,
never pruned). A stale entry for a deleted asset is inert; only the code
that loads that id would ever notice.

## How the runtime finds content assets

`ContentAssetRoot` is the directory (native) or URL base (wasm) that
addresses are resolved against:

- **native default:** the directory containing the executable. Address
  `content/hero/scene.gasset` resolves to `<exe-dir>/content/hero/scene.gasset`.
- **wasm default:** the page origin, fetched over HTTP.

Every workspace example ships its content tree next to its binary with a
`build.rs` that copies `content/` into the target directory. Because all
examples share one Cargo `target/` directory, each example uses its **own**
root so their registries do not collide:

```rust
// build.rs — copy to <exe-dir>/<pkg-name>-content/content/
let output_path = out_dir.ancestors().nth(3).unwrap()
    .join(format!("{}-content", env::var("CARGO_PKG_NAME")?));

// main.rs — point this example's AssetServer at it, before app.run()
#[cfg(not(target_arch = "wasm32"))]
fn set_own_content_root(app: &mut App) {
    let Some(asset_server) = app.get_resource::<AssetServer>() else { return };
    let exe_dir = std::env::current_exe().ok()
        .and_then(|e| e.parent().map(|p| p.to_path_buf()))
        .unwrap_or_else(|| ".".into());
    asset_server.set_content_root(ContentAssetRoot::Directory(
        exe_dir.join(format!("{}-content", env!("CARGO_PKG_NAME"))),
    ));
}
```

On wasm each example is served from its own Trunk origin, so there is
nothing to disambiguate — the default is correct and the override above is
`cfg`'d out. Trunk's `<link data-trunk rel="copy-dir" href="content" …>`
in `index.html` ships the tree, dotfiles (`.registry.toml`) included.

## Loading at runtime

```rust
// by address — the common case
let scene: AssetHandle<Scene> =
    asset_server.load::<Scene>("content/UAL1/scene.gasset");

// by id — used when only an AssetId is available (e.g. a deserialized
// component handle). Resolves through the registry.
let mesh: AssetHandle<Mesh> = asset_server.load_by_id::<Mesh>(id);
```

Both return immediately with a handle; the bytes load on a background task
pool. A registry miss on `load_by_id` fails the load and logs the id — it
does not fall back to anything.

## Editor-authored assets

Some assets have no DCC source — a `Scene` assembled in an editor, for
instance. `save_content_asset` writes one directly:

```rust
use essential::assets::content::save_content_asset;

save_content_asset(&scene, project_root, "content/levels/intro.gasset")?;
```

It writes the `.gasset` file (with `provenance: None`) and upserts the
registry, exactly as `import` does for a sub-asset. The `project_root` is
the source tree under version control — deliberately *not* the exe-relative
runtime root, so a save is not overwritten by the next build.

## Writing a new importer

An importer lives in whatever crate owns the asset types it produces and
implements `asset_import::Importer`:

```rust
use asset_import::{ImportContext, ImportError, Importer};

pub struct MyImporter;

impl Importer for MyImporter {
    fn supported_extensions(&self) -> &'static [&'static str] {
        &["myext"]
    }

    fn import(&self, source_path: &Path, ctx: &mut ImportContext) -> Result<(), ImportError> {
        let doc = parse(source_path)?;

        // Emit each sub-asset by name. `emit` serializes the value, records
        // its resolved AssetId, and captures its `referenced_sub_assets()`.
        for (i, mesh) in doc.meshes().enumerate() {
            ctx.emit(&format!("mesh/{i}"), &mesh_to_engine_mesh(mesh))?;
        }

        // Build same-file cross-references with `sub_asset_id`, so a struct
        // you emit can hold a real `AssetHandle::weak(id)` that resolves to
        // another sub-asset's final address.
        let mesh_id = ctx.sub_asset_id("mesh/0");

        // Record external inputs (an external .bin, a sibling texture) so a
        // future incremental import can tell the source changed.
        ctx.track_dependency(external_path, asset_import::hash_file_contents(&external_path)?);

        Ok(())
    }
}
```

Then register it in `crates/import/src/lib.rs::registered_importers()`.

`ImportContext::emit<T: Asset>` requires the emitted type to implement
`Asset` (`Serialize + DeserializeOwned` + a `name()` tag). There is no
separate DTO trait — the on-disk form of an asset *is* the asset.

## Current limitations

- **No incremental / re-import.** Every `import` run regenerates everything
  from scratch. `track_dependency` records inputs but nothing consumes them
  yet.
- **No cross-source references.** An importer that emits a reference to a
  sub-asset from a *different* source file logs a warning and leaves it
  unresolved (e.g. an OBJ material pointing at a standalone texture).
- **Quantised / morph-target animation panics.** `GltfImporter` hits
  `todo!()` on I8/U8/I16/U16 rotation channels and morph-target weight
  outputs — re-export uncompressed for now.
- **`AssetId` is derived from the address**, so renaming or moving a
  `.gasset` file changes its identity and breaks every reference to it.
  Fix by re-importing or re-saving at the new path. A rename-safe
  minted-id layer is a possible future addition; the `asset_id` header
  field exists as the seam for it.
- **`ImageImporter` always imports as sRGB.** A per-entry colour-space
  hint would need to come from `content.toml` or a filename convention.
